## Part 3 — Remediation plan (TDD)

Order is by dependency: R-1 first (has a red-test anchor), then independent
items. Every code change is verified by the existing 78-test suite (49 unit +
29 e2e) plus targeted checks.

### R-1 — a11y fixes (M-1, M-2, M-3)

- **RED:** tighten `e2e/a11y.spec.ts` to fail on `critical` AND `serious`
  axe violations on the landing page. Expected failures: `aria-allowed-attr`
  (star spans) and `label-content-name-mismatch` (logo link).
- **GREEN:**
  1. `testimonials.tsx:62` — star span gets `role="img"` (aria-label is legal
     on role=img; content stays aria-hidden decorative inside).
  2. `site-header.tsx` — decorative "W" badge span becomes `aria-hidden="true"`
     (visible text then reads "We Care Car Care", contained in the accessible
     name "We Care Car Care — back to top").
  3. `final-cta.tsx:34` — drop `aria-label` from the `<p>`; the visible
     "5.0 · 37 Google reviews" text is the accessible name (stars already
     aria-hidden).
- **Verify:** a11y spec green; full e2e suite green; lighthouse a11y → 1.0.

### R-2 — LCP fix (L-1) — REVISED after plan validation

- **Validation catch:** the hero `<img>` **already carries** `fetchPriority="high"`
  (hero.tsx:18-23), so the originally drafted "add fetchpriority" item was
  wrong. The real lever is payload: the hero is the largest asset at 161 KB
  (1344×768 webp) and is served unchanged to 390px-wide phones. Under
  lighthouse's simulated throttle this dominates the 4.5 s LCP.
- **RED:** extend the e2e smoke hero assertion to require a `srcset` with a
  ≤640w variant on the hero image.
- **GREEN:** generate 640w/1024w hero variants with sharp; add
  `srcSet`/`sizes` to the hero `<img>` (keep `fetchPriority="high"` and the
  1344w fallback for `src`).
- **Verify:** e2e green; lighthouse LCP improves (exact delta throttling-
  dependent); images test still green (no broken src).

### R-3 — delete dead route (L-2)

- Remove `src/app/api/route.ts` (zero references; the real APIs are
  `/api/bookings` and `/api/questions`).
- **Verify:** `bun run build` route table drops `ƒ /api`; lint/tsc/e2e green.

### R-4 — typecheck the e2e suite (L-3)

- tsconfig `include` += `"e2e/**/*.ts"`, `"playwright.config.ts"`.
- **Verify:** `bunx tsc --noEmit` clean; `next build` still green (its
  typecheck now also covers specs).

## Part 5 — Execution log

All four remediation items executed with TDD; every gate re-verified after.

### R-1 — a11y fixes (M-1, M-2, M-3) — DONE

- **RED:** tightened `e2e/a11y.spec.ts` to gate critical AND serious violations
  → confirmed failing (multiple serious findings).
- **GREEN:**
  - `testimonials.tsx` — star-rating spans got `role="img"` (aria-label is
    legal on role=img; the Star icons inside stay aria-hidden).
  - `site-header.tsx` — logo restructured: dropped the `aria-label`, hid the
    decorative "W" badge (`aria-hidden`), appended `<span class="sr-only">
    — back to top</span>` so the accessible name is composed from content —
    Label-in-Name holds by construction. (First attempt — aria-label +
    hidden badge — still failed axe: block-level spans concatenate without
    separators, so "We CareCar Care" was not a substring of the aria-label.)
  - `final-cta.tsx` — removed `aria-label` from the rating `<p>`; the visible
    "5.0 · N Google reviews" text is the accessible name.
- **Verify:** lighthouse a11y 0.97 → **1.0** with **zero** failing rules;
  29/29 e2e green.

### R-2 — responsive hero (L-1, revised) — DONE

- **RED:** hero smoke assertion requires `fetchpriority="high"` + a srcset
  containing a 640w variant → confirmed failing (no srcset).
- **GREEN:** `scripts/hero-variants.mjs` generated `hero-car-640w.webp`
  (44 KB) and `hero-car-1024w.webp` (92 KB) from the 161 KB original; hero
  `<img>` now carries `srcSet` + `sizes="100vw"` (desktop keeps the 1344w
  file; phones download 44 KB — a 73% LCP-payload cut).
- **Verify:** e2e green; lighthouse performance 0.71 → **0.80**, LCP
  4.5 s → 4.2 s, TBT 520 ms → 260 ms, CLS 0.
